## Arquitectura y persistencia

- Frontend: GitHub Pages actual, rutas relativas bajo `/aptis-b2-course/`, sin herramientas de compilación para servir la web.
- Backend: Worker independiente + Durable Object SQLite para presupuestos de llamadas. Endpoints POST Writing/Speaking; secreto `OPENAI_API_KEY` únicamente server-side.
- Writing: `gpt-6-luna`, `medium`, Responses API y JSON Schema.
- Speaking: `gpt-audio-1.5`, audio real WAV desde el Blob existente, salida solo de texto y validación JSON con un máximo de un reintento.
- `aptis-b2-performance-v1` sigue siendo la clave principal. `aptis-b2-vocabulary-v1` sigue intacta.
- Nueva clave `aptis-b2-ai-feedback-v1`: último feedback por ID, timestamp, modelo y hash de la respuesta/grabación. No contiene claves ni audio; no duplica la respuesta completa escrita. Se conservan hasta 200 feedbacks para limitar el uso de espacio local.
- El texto sigue guardándose en el progreso existente. La grabación original sigue solo en memoria. Una recarga conserva el feedback, pero no el audio, como en v1.1.
- Los errores elegidos se añaden con categorías completas compatibles con Error Tracker y Personal errors de Vocabulary Lab; no se añaden automáticamente ni se duplican.
- El import/export existente continúa separado y compatible con sus backups. No se ha extendido su esquema con feedback IA.

## Validación

Pruebas automatizadas del contrato del Worker: IDs desconocidos/tipo incorrecto, texto vacío/corto/largo, caracteres de control, cliente intentando cambiar el prompt, método/origen incorrectos, secretos ausentes, Turnstile inválido, cuotas concurrentes, proveedor 401/429/500, pérdida de conexión, timeout, JSON mal formado, límites del feedback, PCM real recibido y reenviado, silencio/audio corto/largo/inválido/grande y reintento único de Speaking. El modelo usado en estas pruebas es un sustituto **solo de desarrollo**.

Navegador Chrome en contextos aislados, escritorio 1440 px y móvil 390 px: flujo de Writing, contador, doble clic, solicitud lenta, fallos, recarga, texto cambiado, guardado selectivo de errores, Vocabulary Lab leyendo esos errores, práctica extra con respuesta histórica, MediaRecorder, permiso denegado, reproducción/regrabación, envío multipart de audio, feedback, conservación del Blob tras fallar, temporizadores, límite de dos escuchas, 32 sesiones, diagnóstico, biblioteca, mocks, descargas, Error Tracker, export/import válido e inválido, ausencia de pestañas externas, desbordamiento horizontal y errores de página/assets.

Comprobación adicional en el runtime real `workerd`: bundle de Wrangler y Durable Object SQLite con peticiones concurrentes. El Worker local devuelve 503 si faltan secretos, 403 a orígenes ajenos y 405 a GET, según lo previsto.

Pendientes por credenciales/hardware: respuestas reales de los modelos, calidad de corrección B2/B2+, pronunciación sobre voz humana, widget Turnstile real, despliegue cloud y micrófono/navegador móvil real. Sigue los pasos y checklist de `worker/README.md`. Estas comprobaciones no se consideran realizadas por las pruebas con proveedores interceptados.

## Coste orientativo

Precios estándar consultados el 4 de octubre de 2026, USD sin impuestos ni costes de Cloudflare:

- [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): $0,10 / millón de tokens de entrada; $0,50 / millón de salida. Un Writing con 1000–2500 tokens de entrada y 1500–6000 de salida (incluyendo razonamiento) rondaría **$0,0009–$0,0033**. No se ha medido todavía una corrección real.
- [GPT-Audio-1.5](https://developers.openai.com/api/docs/models/gpt-audio-1.5): audio entrada $32 / millón; texto entrada $2,50 / millón; texto salida $10 / millón. No se solicita audio de salida.

Para Speaking, un escenario ilustrativo con 10–25 tokens de audio por segundo y unos 1500 tokens de instrucciones/tarea + 800 de salida da aproximadamente:

| Grabación | Una llamada, coste ilustrativo |
| --- | ---: |
| 30 s | $0,02–$0,04 |
| 45 s | $0,03–$0,05 |
| 2 min | $0,05–$0,11 |

La relación tokens/segundo no está verificada para este endpoint y estos clips; este intervalo es una hipótesis de presupuesto, no una tarifa por minuto. Confirma con el campo `usage` del proveedor una vez hechas llamadas reales. Una respuesta más larga o un reintento aumenta el coste. Los límites del Worker cuentan llamadas/reservas, no dólares. También conviene establecer un presupuesto del proyecto de OpenAI desde su panel.
